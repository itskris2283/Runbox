   - Strict multi-tenant isolation with anti-enumeration protection (HTTP 404 for foreign tenant resources).
   - In-memory sliding-window rate limiting (HTTP 429 with `Retry-After`).

## 3. SECURITY ARCHITECTURE & HARDENING AUDIT

### 3.1 Process & Namespace Isolation (`core/namespaces/namespaces.cpp`)
- **Isolation Boundary**: The supervisor unshares six independent namespace boundaries (`CLONE_NEWUSER`, `CLONE_NEWPID`, `CLONE_NEWNS`, `CLONE_NEWNET`, `CLONE_NEWIPC`, `CLONE_NEWUTS`).
- **User Namespace Mapping**: Uses `write_id_mappings` to map the outside unprivileged user UID to inside UID 0 (root), granting container authority without host escalation.
- **PID Namespace Reaping**: Workload executes as PID 1 inside the private namespace. An intermediate supervisor process reaps child processes and propagates exit codes.

### 3.2 Hardware Resource Governance (`core/cgroups/cgroup_manager.cpp`)
- **Memory Enforcement**: Governed by `memory.max`. Swap is disabled via `memory.swap.max = 0`. Cgroup OOM killer terminates the container if memory limits are exceeded.
- **CPU Quota**: Enforced via `cpu.max` (e.g., `50000 100000` for 50% CPU limit).
- **Process Cap**: Governed by `pids.max` (defaults to 32), mitigating fork bombs.
- **Atomic Teardown**: Uses `cgroup.kill = 1` for immediate kernel-level termination of all processes in the cgroup upon timeout or completion.

### 3.3 Ephemeral Filesystem & Landlock LSM (`core/filesystem/filesystem_isolation.cpp`)
- **Mount Isolation**: Private mounts (`MS_REC | MS_PRIVATE`) ensure host mount namespace changes do not propagate into the sandbox.
- **Filesystem Boundaries**: Bounded tmpfs mounted on `/workspace` and `/tmp` with `nr_inodes=10000` to prevent inode exhaustion attacks.
- **Landlock Access Control**: Kernel-enforced VFS restrictions:
  - Read-only execution: `/usr`, `/lib`, `/lib64`, `/bin`.
  - Read-only metadata: `/etc` (host credentials like `/etc/shadow` are replaced with a minimal synthetic passwd file).
  - Read/write access: Scoped strictly to `/workspace`, `/tmp`, and `/mnt`.

### 3.4 Syscall Filtering (`core/seccomp/seccomp_rules.cpp`)
- **Fail-Closed Default**: Default action is `SCMP_ACT_ERRNO(EPERM)`.
- **Hostile Syscall Auto-Kill**: Syscalls such as `ptrace`, `bpf`, `reboot`, `mount`, `umount2`, `pivot_root`, `setns`, `unshare`, `chroot`, `kexec_load`, and kernel module loaders trigger immediate process termination (`SCMP_ACT_KILL_PROCESS`).
- **Profile Allowlisting**: Dedicated profiles for Minimal, Python, C++ Compilation, and C++ Execution allow only the minimum syscalls necessary.

### 3.5 Privilege Model (`core/security/privileges.cpp`)
- **No New Privileges**: `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)` is strictly applied before filter loading or execve.
- **Capability Removal**: Ambient capabilities cleared; all 64 bounding set capabilities dropped.
- **Supplementary Groups**: Cleared via `setgroups(0, NULL)`.
- **Core Dumps Disabled**: `RLIMIT_CORE = 0` prevents dumping sensitive process memory to disk.

### 3.6 Control Plane & Multi-Tenant Security (`api/security/`)
- **Cryptographic Token Verification**: SHA-256 digests compared via `secrets.compare_digest()`.
- **Anti-Enumeration Defense**: Cross-tenant requests to foreign executions return HTTP 404 (indistinguishable from nonexistent IDs).
- **Sliding-Window Rate Limiting**: Enforces rate limits with HTTP 429 and `Retry-After`.
- **Concurrency Quotas**: Prevents any single tenant from consuming more than 5 concurrent execution slots.
- **Payload Bounds**: HTTP 413 enforced on request bodies exceeding 1 MB.
